# Трекер полезных привычек

Бэкенд SPA-приложения по мотивам книги Джеймса Клира «Атомные привычки».

Привычка описывается одной фразой: **я буду [ДЕЙСТВИЕ] в [ВРЕМЯ] в [МЕСТО]**. За выполнение полагается награда, а напоминания приходят в Telegram.

## Стек

- Python 3.12+
- Django 5.2
- Django REST Framework
- djangorestframework-simplejwt — JWT-авторизация
- drf-spectacular — OpenAPI-документация
- django-cors-headers — доступ для фронтенда
- Celery + Redis — фоновые и периодические задачи
- requests — обращения к Telegram Bot API
- SQLite (переключается на PostgreSQL одной переменной)

## Установка

```bash
poetry install --no-root
cp .env.template .env
```

Заполните `.env` — минимум `SECRET_KEY` и `TELEGRAM_BOT_TOKEN`. Файл `.env` в репозиторий не попадает.

```bash
poetry run python manage.py migrate
poetry run python manage.py createsuperuser
poetry run python manage.py runserver
```

Сервер поднимется на http://127.0.0.1:8000/

## Модель привычки

| Поле | Что означает |
|---|---|
| `user` | Создатель привычки |
| `action` | Действие — что именно делать |
| `time` | Время напоминания |
| `place` | Место выполнения |
| `is_pleasant` | Признак приятной привычки |
| `related_habit` | Связанная приятная привычка |
| `periodicity` | Раз в сколько дней, от 1 до 7 |
| `reward` | Вознаграждение, если не выбрана приятная привычка |
| `duration` | Время выполнения в секундах, не больше 120 |
| `is_public` | Видна ли привычка всем |

### Полезная, приятная и связанная

**Полезная привычка** — действие, за которое человек себя награждает. Награда бывает двух видов: приятная привычка в поле `related_habit` либо что-то другое в поле `reward`.

**Приятная привычка** — сама по себе награда. Ей не нужны ни `reward`, ни `related_habit`.

Пример: «я буду гулять вокруг квартала в 19:30 у дома», а наградой будет приятная привычка «принять ванну с пеной». Другой вариант: «я буду не опаздывать на встречу с друзьями», награда — десерт, и тогда заполнено поле `reward`.

## Валидаторы

Лежат в `habits/validators.py`, подключаются в `Meta.validators` сериализатора.

| Правило | Сообщение при нарушении |
|---|---|
| Нельзя указать награду и связанную привычку одновременно | «Выберите что-то одно…» |
| Время выполнения не больше 120 секунд | «Время выполнения не должно превышать 120 секунд…» |
| В связанные попадают только приятные привычки | «Связанной может быть только приятная привычка…» |
| У приятной привычки нет ни награды, ни связанной | «Приятная привычка сама является наградой…» |
| Периодичность от 1 до 7 дней | «Нельзя выполнять привычку реже, чем раз в 7 дней…» |

Валидаторы объявлены с `requires_context = True` и получают сериализатор. Это нужно для `PATCH`: недостающие поля добираются из объекта в базе, иначе частичное обновление обходило бы проверки.

Дополнительно: связать можно только со своей привычкой — иначе по чужому id можно было бы узнать, что у другого пользователя есть привычка с таким номером.

## Права доступа

| Кто | Что может |
|---|---|
| Аноним | Только регистрация и получение токенов |
| Авторизованный | CRUD своих привычек, просмотр публичных |
| Владелец | Всё со своей привычкой |

Чужая привычка не просто закрыта — она отфильтрована на уровне выборки и возвращает **404**, а не 403. Так наружу не утекает даже факт её существования.

Публичная витрина не раскрывает автора: показывается сам приём, а не то, кто его придумал.

## Пагинация

`LimitOffsetPagination`, по пять привычек на страницу. Ответ:

```json
{
  "count": 12,
  "next": "http://127.0.0.1:8000/api/habits/?limit=5&offset=5",
  "previous": null,
  "results": [ ... ]
}
```

Размер страницы меняется параметром `limit`, смещение — `offset`. Больше 100 за раз отдать нельзя: иначе одним запросом можно было бы вытащить всю базу.

## Напоминания в Telegram

### Как завести бота

1. Написать [@BotFather](https://t.me/BotFather) команду `/newbot`
2. Указать видимое имя и юзернейм — он должен заканчиваться на `_bot`
3. Скопировать токен в `.env` в переменную `TELEGRAM_BOT_TOKEN`

### Как связать пользователя с чатом

Бот не может писать первым — сначала человек должен написать ему сам.

1. Пользователь открывает бота и отправляет `/start`
2. Администратор выполняет:

```bash
poetry run python manage.py fetch_chat_ids
```

Команда покажет найденные `chat_id`. Привязать к аккаунту:

```bash
poetry run python manage.py fetch_chat_ids --email user@example.com
```

Либо пользователь сам сохраняет свой `chat_id` через `PATCH /api/profile/`.

### Как работает рассылка

Задача `notifications.tasks.send_habit_reminders` запускается celery-beat раз в минуту и:

1. Берёт привычки, чьё время попадает в окно последних `REMINDER_WINDOW_MINUTES` минут
2. Отбрасывает пользователей без `telegram_chat_id` и заблокированных
3. Проверяет периодичность: привычка «раз в три дня» не напоминает ежедневно
4. Отправляет сообщение и только **после успешной отправки** ставит отметку `last_reminded_at`

Последний пункт важен: если телеграм не ответил, отметка не ставится и следующий запуск попробует снова.

Окно в несколько минут нужно на случай, когда воркер был занят или лежал — напоминание уйдёт с задержкой, а не пропадёт совсем. Отдельно обработан переход через полночь: окно 23:57–00:02 это два отрезка, обычное «между» дало бы пустую выборку.

### Запуск

Три процесса в трёх окнах, Redis должен работать.

```bash
# 1. Django
poetry run python manage.py runserver

# 2. Воркер
poetry run celery -A config worker -l info

# 3. Расписание
poetry run celery -A config beat -l info
```

На **Windows** воркеру нужен режим `solo` — обычный пул процессов там не поддерживается:

```powershell
poetry run celery -A config worker -l info -P solo
```

## CORS

Фронтенд живёт на другом домене, и без настройки браузер заблокировал бы запросы к API. Разрешённые домены задаются переменной `CORS_ALLOWED_ORIGINS` через запятую.

`CorsMiddleware` стоит в списке выше `CommonMiddleware` — иначе заголовки не попадут в ответ.
